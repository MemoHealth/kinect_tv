# Test plan (unit -> integration -> physical experience)

## Unit tests (no camera)

- SensorFrame rejects invalid type/shape/timestamp; stale frames discarded.
- Depth mask uses closer-than-background criterion, invalid zeros ignored, component filtering and smoothing do not fill whole screen.
- Person enters/leaves active state through debounce/hysteresis and decays after loss.
- Mirror and letterbox coordinate transforms are invertible within tolerance and applied once.
- Finite-difference normal and collision response for horizontal/vertical/sloping outline; high velocity does not tunnel through arm-thin mask.
- Force field localizes around moving foreground, decays and clamps magnitude; still silhouettes create no spurious gust.
- Fixed-timestep simulation deterministic at given seed; particle count capped; stable after 500+ synthetic frames.
- Settings schema accepts supported values, rejects invalid config and migrates old version with safe defaults.
- Input handling: keyboard parent shortcuts only, hidden menu never generated by pose or simulated hand movement.

## Integration tests (CI, --demo)

- Headless engine test runs 60 s at accelerated virtual time with 1/2/3 shapes, including rapid motion, pauses and invalid frames.
- GUI smoke test launches with `--demo --windowed` in controlled environment and produces a synthetic frame screenshot to compare with an approved baseline (do not rely on brittle pixel-perfect comparison for all particles).
- Input switch: missing real hardware => `NO_DEVICE` state; never automatic simulated fallback.
- No network requirement after package installation; monkeypatch/deny network calls during test.
- Tests prove RGB=None and pose_magic=False produce interactive effects.
- Memory test ensures no unbounded particle/frame accumulation.

## Manual real hardware matrix (owner)

1. Kinect v1 on the target PC: correct adapter/USB, depth frame unit and fps check.
2. 1.2–3.5 m working distances where room permits; record actual near/far and identify blind spots rather than assert universal range.
3. Child-sized silhouettes at varied heights, adult silhouette, and groups of two and three. Check that all three can affect the rain at once when visible, with a shared silhouette when they partly overlap.
4. Bright room, dim room, furniture in background, loose/dark clothes, arm extended, crouched/seated.
5. Child walks into/out of field; fast movement; close foreground; turned side-on.
6. USB disconnected/reconnected mid-session; alt-tab, TV power/input cycle, fullscreen resolution change.
7. 30 min soak (FPS, temperature if available, memory, dropped frame behavior).
8. Measure action-to-effect latency and sensory comfort; log actual observations and hardware specs.

## Child usability test (privacy respectful)

Caregiver present. Do not ask children to perform a checklist of gestures or record identifiable video without explicit informed adult permission; prefer written observation notes: time to first meaningful action, verbal explanation needed Y/N, child attempts, delight/frustration signals, any physical safety concern, motion sickness/sensory overload. Minimum two tests of different age/height before UX-06 can be marked observed; more is better. No names or identifying information in project logs.

## Required report per PR

Issue ID; requirement IDs; automated commands/results; `--demo` outcome; hardware tested Y/N + exact test and outcome; known limitations; screenshots only from synthetic footage by default; docs changed; one review decision. Label unexecuted tests explicitly `NOT RUN`, not success.
